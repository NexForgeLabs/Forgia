# C6 optional VM boundary and original Mod Worker path — implementation notes

This is an implementation checkpoint from `2fe7ff74aa63f7fcc9fe34efeaadb14aa5243f0f`, published at the user's request to organize and preserve the current work. **C6 final architecture acceptance remains pending.** The current code includes the optional production mechanism and source-only reproduction tools; earlier complete real-Mod results and the latest component results belong to explicitly recorded source revisions. A successful component or filtered GameTest does not certify an arbitrary Modpack or establish an MSPT improvement. The [checkpoint receipt](MOD-WORKER-RUNTIME-CHECKPOINT.json) records actual commands, exits, hashes and unfinished gates.

The optional `runtime-proof` project supplies a bootstrap Java bridge and a Linux/JDK 21 native JVMTI service. Default startup does not load this service. Core discovers an actual bootstrap definition before loading any class that implements its access callback; an absent service keeps the original Mod ticker serial. The v1 Adapter APIs do not issue this evidence or receive an execution handle.

The service reads actual installed JVM bytecodes, constant pools and exception-handler counts, including hidden classes. This replaces the earlier dependency on observing lambda factory metadata: the original function object taken from the real LevelChunk delegate is the function whose actual class and reached methods are checked. No alternate factory is called and no replacement ticker is made. Defining loader/Class identities are resolved from the VM's already loaded class set, without invoking a supplied ClassLoader or initializing a new target class. Classes on the accepted path must already be initialized. Returned descriptions copy mutable bytes and are not accepted back as proof inputs.

A small semantic verifier accepts the actual SAM forwarding shape, its single static four-argument forwarder, and the actual final direct BlockEntity subclass's original method. The supported current path performs the original integer increment and returns when the new value has a nonzero remainder. The periodic branch remains unknown and the complete invocation stays serial before any body starts. Java integer overflow and remainder semantics are preserved. The mechanism contains no third-party Mod id, class-name or hash allowlist. Original installed code outside this closed shape refuses.

The selected real upstream integration artifact is 方块电玩 / `piq_fc_arcade` 0.31.0-alpha.61. Its original hidden function calls the final FurnitureBlockEntity's original maintenance method. The artifact is private and All Rights Reserved; no upstream jar, class bytes or decompiled implementation is included in this repository change. Artifact hashes identify test inputs only. They do not confer execution authority.

Original Core/Vanilla wrapper methods are a separate trusted base. The build can produce a bootstrap bundle containing this exact build's own compiled Core/Vanilla integrity metadata. Final named class-definition events are bound to the actual defining loader. Comparison includes method instructions, invokedynamic bootstrap arguments, handlers, descriptors and access flags. Unknown added dispatch targets refuse; the existing BlockEntityType valid-block registration setter is accepted only by its exact setter semantics. Immutable code integrity may be cached by actual Class identity and VM definition epoch; the invocation's counter, storage, binding, lifecycle, Claims and reservation remain freshly checked.

Before publication, Core verifies the wrapper's prerequisites without running an unknown Supplier or collection implementation. It interprets the actual captured profiler getter and requires the inactive profiler, interprets the exact ChunkHolder full-status getter, requires a stationary exact Core border extent, and checks block membership by identity in a recognized immutable collection. Workers consume the captured Core prerequisites and execute the entire original third-party function. They do not re-enter the shared profiler Supplier, block-type collection or chunk BE map. Native Hopper and Furnace continue their existing wrapper conditions outside the Mod scope.

The real source BE, outer wrapper, bound delegate and actual immutable position are four distinct storage roots. The source root owns the primitive counter; copied/boxed counter values and function singleton identity do not split that storage. The source/delegate have WRITE Claims and the wrapper/position have READ Claims. The containing chunk is checked before publication and retained only as an opaque frame identity: the Mod Worker reads no live Chunk and takes no Chunk Claim, so normal managed light-completion writes are not blocked by this proof. The original wrapper uses captured Core context before invoking the original third-party function.

Mutable roots have inherited-field and method-entry checks. Normal PUTFIELD/GETFIELD, reflective and MethodHandle/VarHandle/Unsafe operations and JNI field APIs must participate in the same actual access check. Method entry checks reject an unparticipating public instance method before its earlier side effects. Bytecode field access remains active until the following instruction, so a check is not mistaken for completed access. For exact, integrity-verified Core BlockPos values, VM registration instead freezes every inherited instance field: even a current owner cannot write it afterward, while coordinate reads need no mutable-object guard. This is enforced immutability of the actual object, not permission based on a private/final field declaration; it says nothing about arbitrary reachable objects.

The native table holds weak interception metadata only. It cannot reserve, transfer, release or grant ownership. Every mutable-root access callback consults the original Core Resource Scope, coarse Region owner, or idle server coordinator. A short publication interlock prevents an already-started access from straddling the original Claims reservation. The callback runs outside the native monitor to avoid reversing the Core lock order. Queued work remains excluded by the still-held original Region state; Scope exit is not physical join and does not release the outer authority.

A reproduced counterexample showed that the old callback-recursion bypass could let a callback registered for a different object enter a protected writer. The retained red test changed both the guarded value and its earlier side-effect counter. The current native boundary denies every nested entry/read/write of protected mutable roots during a callback and keeps native bounds/header checks active. Frozen values still reject every write. Core's Furnace compatibility check now compares original Scope/Ticket wrapper identities without invoking protected ticker getters from its metadata callback. The repaired standalone counterexample requires zero value/earlier-effect changes; it does not mint a Core Lease. Final real-Level compatibility of this last change is not yet accepted.

The supported VM profile disables attach and Unsafe intrinsic inlining and accepts only the one startup native service. Unknown native libraries are refused before JNI_OnLoad. Native FFI downcall creation and the JMX diagnostic native-agent-load route are refused before execution. Known JDK native allocations, VM thread-id storage, perf buffers and read-only module-image mappings are bounded separately from heap-object field offsets. These controls deliberately restrict the supported profile; this is not a hostile JVM/Core memory-corruption sandbox, nor a promise to support every JNI/JNA Mod. Rejected and unsupported environments keep Mod Worker admission unavailable.

A Core-created manifest is attached to the original INSPECTED Ticket. Actual resource roots become the existing READ/WRITE Claims, using the same phase resource-home tokens and cumulative budget as Furnace. The original planner, whole-wave reservation, one-shot Lease, thread-bound Scope, Region exclusion, worker pool, Kernel Permit and canonical cursor remain the authority chain. The Kernel requires the exact Claims object reserved for that Ticket and an actually entered Scope. It cannot promote a started Serial Permit. Rebind/replacement does not inherit a manifest. Unknown registered Adapter types remain complete Serial Fences with their established callback timing.

The implementation retains a contiguous prefix, performs all gate checks before any prefix body, physically joins every submitted task, seals the original guards and only then releases resources and outer Region leases. Started body or cleanup failure never triggers serial replay. The current closed counter body has no world/provider/event/effect-commit call; unknown paths do not obtain a generic effect or rollback protocol.
