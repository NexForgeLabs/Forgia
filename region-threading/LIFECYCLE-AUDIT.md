# Lifecycle audit and test design

Audit baseline: clean `main`, `acd5207cbbe55e138cb9ba6c30b774b7322b1bc0`. This is a separate lifecycle investigation. `C6 FINAL ARCHITECTURE ACCEPTANCE: PASS` and its report/receipt are frozen. No production changes are proposed at this stage.

## Reference-retention map (before implementation)

| Owner / root | Strong references while live | Weak references / retirement |
|---|---|---|
| MinecraftServer | `levels` -> real ServerLevel -> chunk source / ChunkMap -> LevelChunk -> block entities / bound ticker wrappers; server thread and pending tasks | `stopServer` saves, posts LevelEvent.Unload, closes every Level and storage. It does **not** clear `levels`. Collection of the entire stopped server graph is the supported whole-server boundary; clearing its map in a test would invent a boundary. |
| LevelChunk ticker binding | wrapper -> delegate -> original Mod function / original BE; captured binding -> chunk / Level / source / delegate | Rebind increments the Core version; captured frame identity/version checks deny old admission even if delegate is unchanged. Normal replacement invalidates source identity. |
| RegionThreadingManager | atomic current -> engine | `handleServerStopped` -> manager.clear -> engine.shutdown; finally compareAndSet uninstalls the captured engine. |
| RegionThreadingEngine | regionizer / coordinates / section/entity indexes -> Level; active batches; mailboxes, tick phases, deferred seams, worker-server queues; canonical planner and work graph | Level clear awaits complete published phases and submitted tasks, closes Level identity, removes indexes/queues and cancels tasks. Closed Level identities are weak keys in ThreadedRegionizer. Shutdown stops admission, awaits phases/tasks, clears queues/regions, physically closes pool. |
| Canonical phase / invocation Kernel | phase -> Level, ordered admissions, Ticket map; Ticket -> admission, Mod manifest, exact Claims, effects; manifest -> LevelChunk, original source/ticker/delegate, Region and frame; Claims -> identities/bindings/freshness closures | Phase close requires zero active permits/guards; cancels unstarted Tickets, sets proof RETIRED, nulls manifests/Claims, clears effects and Ticket map. A deliberately retained external Ticket still contains its admission: such a reference is not an idle Core root. |
| Reservation / Lease / Scope | resource owner -> active leases -> Claims; entered scope and Permit -> exact Lease / Ticket; worker ThreadLocals -> contexts, Mod manifest, resource and Region authority | Worker return closes subordinate scopes/ThreadLocals and Permit; actual join precedes guard seal, ordered commits, resource owner closure, outer Region release and phase completion. Resource exclusion must remain until join. |
| Worker pool | queued callbacks -> batch/guard/manifest/Level; running callback and thread stack -> same graph | Accepted work drains; cancellation of managed wait still physically joins. Pool close waits for actual thread termination. It never releases resources to make a stalled worker appear joined. |
| CoreModPreparation | engine -> preparation -> root metadata and AccessAuthority callback | Protected source keys weak. AccessAuthority holds weak engine, Level, coordinator Thread and home Region. | Optional native interception | weak JNI protected-root keys; **strong JNI global references to callbacks**; loaded-class/installed-code evidence | Callback weak owners are essential: retaining a callback must not pin a retired world. Native registration prunes dead weak keys on subsequent registrations. Metadata itself is not a Permit, reservation or lifecycle manager. |
| Test framework / GameTest harness | GameTestTicker singleton -> runner -> test infos -> real Level; observers/sequence closures can retain complete fixtures | GameTestTicker.clear is the harness's explicit stop API. ## Transition map

`normal loadLevel -> real LevelEvent.Load -> chunk load / original ticker registration -> canonical collection -> published phase -> fresh Core manifest / inspected original Ticket -> atomic all-or-none Claims -> exact one-shot Lease -> queued callback -> entered Region / Permit / resource Scope / CoreModWorkScope -> original body -> scope return -> physical task join -> guard seal -> ordered commit -> resource release -> outer Region release -> execution retirement -> published phase completion`.

Level retirement: `LevelEvent.Unload -> NeoForgeEventHandler.onDimensionUnload (HIGHEST) -> RegionThreadingHooks.clearLevelRegionTasks -> engine lifecycle write gate -> await published phase and submitted work -> close identity under admission lock -> clear regionizer / deferred queues / mailbox / entity tasks -> FakePlayerFactory.unloadLevel -> ServerLevel.close`. Repeated clear remains closed and cannot recreate admission.

Whole shutdown: `ServerStoppingEvent -> MinecraftServer.stopServer saves and unloads/closes Levels -> handleServerStopped event / adapter close -> RegionThreadingManager.clear -> engine.shutdown stops admission / closes seams / awaits published work / clears regions and queues / pool.close physical join -> static server providers cleared -> GameTestServer.onServerExit -> server thread return`.

Rebind/replace checks run through the existing captured frame and exact Ticket/Claims. An unload request racing a published phase waits through its complete suffix and cleanup; it does not independently cancel/release an entered Lease. Lifecycle calls from a participating worker or its active coordinator reject self-wait before monitors. Region retirement requires quiescence and clears guard attachment only after subordinate work returns. Cleanup failure aggregation preserves the first Throwable and suppresses later distinct failures; unchanged tests exercise this behavior.

## Observed implementation and diagnostic corrections

The Level-close observation Mixin in retained attempt `gc-fixed-3` changed an integrity-checked Core method. Production correctly refused Mod Worker admission (`ServerLevel.close()V differs from audited Core build`); the test's Worker assertion then crashed the server. That Mixin was removed. The delivered test transforms **only** `GameTestServer.onServerExit`'s final `System.exit`, and observes the unchanged Level-close terminal state through its original sealed entity ledger and entity IOWorker's shutdown flag/CLOSED mailbox bit. It never replaces the Core integrity manifest or alters the allowlist.

Retained attempts `gc-fixed-4` and `gc-fixed-5` observed 40 real collections each, but retained the server, all three Levels, two chunks and two wrappers. The 20 references to original Mod sources/delegates and execution objects had cleared. A live heap dump and a read-only HPROF search excluding `java.lang.ref.Reference.referent` found this strong path:

`observer Java-frame root -> terminated server Thread -> Thread.holder -> FieldHolder.task -> MinecraftServer startup lambda -> AtomicReference.value -> GameTestServer -> worldArray -> real ServerLevel`.

The observer had both a local and a lambda capture of the joined server Thread. The corrected observer transfers the thread through a one-shot AtomicReference, physically joins it, clears that temporary reference, and captures only the primitive original exit status in its own thread task. No field of the server, stopped Thread, Core engine or world was cleared by the fixture. The subsequent Fixed and Persistent runs each observed all 28 reference queues/weak clearings with three complete observations across four observed collections, while retaining the shutdown engine and six actual access callbacks.

## Runtime Mod unload capability

Pinned installed binaries: FML `4.0.42`, ModLauncher `11.0.5`, SecureJarHandler `3.0.8`, Minecraft `1.21.1`. Full private/public API and relevant bytecode inventories are retained under `tmp/lifecycle-20261115/capability/` with binary SHA256 and exact javap commands/exits. `ModList.INSTANCE`, its loaded containers and indexed map are process-wide; `FMLModContainer` retains loaded classes/module and its event bus. `FMLLoader.gameLayer` and ModLauncher's completed layers remain live. The installed lifecycle event set has construct/setup/IMC/load-complete events, with no runtime unload/reload lifecycle, drain protocol or per-Mod classloader retirement API. `ModLoader.cancelLoading` is an internal startup-failure route, not runtime Mod retirement. `ModuleLayerHandler.updateLayer` accepts an observer/consumer of existing layer info; it is not a supported Mod removal operation.

Repository `CommonModLoader.begin/load/finish` builds/freezes registries, performs startup events and locks networking. `ServerLifecycleHooks.handleServerStopped` unloads **server configs**, adapter registrations and server/engine providers; it does not dismantle ModList, the game layer, registry entries or arbitrary Mod listeners. The real post-server observation confirms the original `piq_fc_arcade` container and its exact `TransformingClassLoader` remain loaded after the world boundary.

The platform supports world/server retirement and scoped adapter registration closure. Removing an adapter, stopping server configs, removing an event listener, deleting a JAR, replacing a loader, or datapack reload is not actual Mod hot-unload. Java21 JLS §12.7 permits class unloading only when the defining loader may be reclaimed; a live shared game loader cannot independently unload one Mod's classes. Genuine runtime Mod unload/reload remains **NOT CERTIFIED**. No simulated unload API or competing lifecycle authority was introduced.

Supporting platform descriptions: [NeoForge 1.21.1 Mod lifecycle](https://docs.neoforged.net/docs/1.21.1/concepts/events#the-mod-lifecycle) says lifecycle events run once during startup; [Java21 JLS §12.7](https://docs.oracle.com/javase/specs/jls/se21/html/jls-12.html#jls-12.7) specifies the defining-loader collection condition. The installed binaries and actual server observation, rather than a general documentation claim, bound this conclusion.

## Real-Level GC design

Use the existing real-server launch, original local `piq_fc_arcade` artifact and existing Core Mod Worker path. Obtain all actual Levels from the server created by MinecraftServer.loadLevel; place two original block entities in separate Regions in the End. Observe exact original Worker executions, counter deltas, current Permit/resource/Mod scopes and callbacks. After phase return remove the testing body observer. Keep the **shutdown engine and actual access callbacks strongly reachable throughout GC**, tracking server, Levels, chunks, original instances, ticker delegates and execution authorities only by WeakReference with ReferenceQueue.

Let the server naturally save, post its actual Level unload events, close storage and execute handleServerStopped and canonical engine/pool shutdown. An opt-in test Mixin intercepts only GameTestServer.onServerExit's final System.exit: capture the original test exit status, clear GameTestTicker with its public stop API, start a non-Worker observer and return. After the unchanged close loop, the original server thread reads each Level's existing closed-storage state. The observer then physically joins that thread, drops the temporary Thread reference, and asserts that installed/server providers are empty and the observed original Mod Worker threads have terminated. No server map clearing, native callback removal, arbitrary finalization or parallel lifecycle manager.

Observe bounded repeated GC requests, actual GC MXBean count deltas, reference-queue arrivals, weak clearing and repeated cleared observations separately. Wait on ReferenceQueue with a bounded timeout, not arbitrary sleeps; do not use System.runFinalization. Emit a separate machine result and retain original server status. A still-retained referent fails collection and produces diagnostics of known roots; no wrapper/mock collection is acceptable. Both persistent and fixed original pools are relevant to this test-only boundary.

Potential limitation identified before implementation: the GameTest runner normally System.exit's inside onServerExit and holds a static runner. The opt-in observer must document this harness instrumentation and must never present the running-server Level map as a collectible object.

Runtime Mod unload capability investigation follows the real-Level experiment. It must inspect the installed NeoForge/FML lifecycle and exact binaries; unregister/disable, Level unload, whole-server shutdown and Java class unloading are different boundaries. Unsupported hot-unload will remain NOT CERTIFIED.
