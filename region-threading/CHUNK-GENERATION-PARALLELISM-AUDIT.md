# Chunk generation parallelism audit

Audited source: initial HEAD `506e3707a80884140dd68b2bd51211e40aa879b4` and the unchanged generated Minecraft 1.21.1 source under `projects/neoforge/src/main/java`. This session does **not** expand chunk-generation admission. Existing vanilla asynchronous generation is not a newly delivered Forgia feature.

The actual path is `ChunkMap.scheduleGenerationTask` → `ChunkGenerationTask.runUntilWait/scheduleLayer` → `GenerationChunkHolder.applyStep` → `ChunkStep.apply` → `ChunkStatusTasks`. `ChunkGenerationTask.create` acquires the existing generation-holder neighborhood through `StaticCache2D`. Each layer awaits its futures before proceeding; cancellation releases holder references after scheduled work completes. `ChunkPyramid` specifies accumulated dependencies and write radii. The worldgen mailbox and vanilla background executor are existing infrastructure, separate from region *tick* admission; this audit creates neither a scheduler nor a resource authority.

| Stage | Existing execution and mutable inputs | Safety classification | Required boundary |
|---|---|---|---|
| EMPTY | Existing asynchronous chunk read, then main-thread reconstruction | Serialized world construction | Loading audit applies |
| Structure starts | Worldgen mailbox; generator, structure manager, template manager, `onStructureStartsAvailable` | Explicit ownership/dependency tracking; unknown callbacks serialized | Shared structure/template caches and mod structure factories are not immutable inputs |
| Structure references | Worldgen region; radius 8 STRUCTURE_STARTS dependency | Explicit dependencies | Reads neighboring starts and writes the center's references; preserve original traversal and status futures |
| BIOMES | `NoiseBasedChunkGenerator.createBiomes` uses `CompletableFuture.supplyAsync(Util.backgroundExecutor())` | Parallelizable with immutable/certified inputs; already asynchronous for vanilla noise generator | RandomState, Blender and biome-source implementations require actual implementation audit; arbitrary mod sources are not certified |
| NOISE/terrain | `fillFromNoise` uses the vanilla background executor and acquires/releases section containers; radius 1 BIOMES and radius 8 starts; write radius 0 | Explicit chunk ownership/dependencies; already asynchronous in the vanilla implementation | Center ProtoChunk, NoiseChunk cache, aquifers, heightmaps, blending and retrogen are mutable. One status owner per holder; never concurrently mutate the same ProtoChunk |
| Surface | Worldgen mailbox; radius 1 BIOMES, radius 8 starts; write radius 0 | Explicit dependencies and callback certification | Surface rules/material callbacks and cached noise access are not generically pure |
| Carvers | Worldgen region; radius 8 starts; write radius 0 | Explicit ownership and dependencies | Carving masks, center blocks, neighbor biome inputs and seeded random streams must preserve order |
| FEATURES | Worldgen region; radius 1 CARVERS, radius 8 starts; write radius 1 | Required serialized overlap unless disjoint neighbor write sets are proven | Features/structures can write neighboring chunks; a center-only region lease is insufficient. | SPAWN | Worldgen region with radius 1 BIOMES | Serialized unknown callbacks/entity construction | Entity factories, spawn hooks and world registration are not pure noise calculations |
| FULL | Explicit supplyAsync onto the **main-thread** mailbox | Required serialized | Proto→LevelChunk conversion, post-load entities, block-entity registration, tick containers, NeoForge ChunkEvent.Load and currentlyLoading deadlock bypass remain original |

A future safe expansion must use the existing holder/status futures as the dependency source. It must prove both the *read* neighborhood and every possible write destination; status asynchrony alone is not that proof. Seed-derived RNG objects and the original stage order must remain unchanged. Cancellation must stop new admissions, physically join started work, discard unpublished private results, and release each original holder reference once. No worker exception may trigger replay of a partially mutating stage.

The C6 Kernel currently grants original block-entity invocation Tickets bound to exact ticker/source/Level identities. It has no chunk-generation descriptor or ProtoChunk storage manifest. Reusing the pool alone would bypass that authority; creating a separate generation reservation/lease map would violate the architecture constraint. No admission is therefore added by this session. Unknown generator, biome, structure, surface, feature and spawn callbacks retain their existing behavior and conservative serial boundary; Create remains serial.

Validation scope: source audit plus existing world-generation activity in disposable normal-preset production soaks. These soaks do not compare complete generated chunk hashes under varied generation schedules. New deterministic seed/hash, neighbor-boundary, cancellation/failure, save/reload and mod-callback parity tests for a new generation implementation were **not executed**, because no new implementation was admitted. Throughput comparisons for new parallel generation are N/A. Assessment: **NOT YET** for additional Forgia generation parallelization; existing vanilla biome/noise futures are explicitly distinguished.
