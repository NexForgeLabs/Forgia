## Evidence and fixes

1. **Tasks submitted before a region drain is due.** Initial source submitted one drain per region and only tested its timer inside the worker. In accelerated/managed drains many submissions were already known to have no due work. The fix tests the same timer under its original region monitor before marking/submitting. Existing accepted/running work is still awaited **before** the early return, and the worker retains its original due check. Logical queue deadlines are not advanced at admission. The new deterministic test holds a future deadline, proves20level drains create0submissions/0logical queue ticks, then makes the original timer due and proves exactly one body/submission/tick. The107selected baseline safety tests passed. Same6000tick soak mean8.274→8.108ms; P99 16.456→17.234ms. This is a small mean result with no demonstrated tail win.

2. **Canonical furnace lookahead repeats expensive catalog and whole-phase alias scans per invocation.** The64-furnace installed fixture measured10.28–10.43ms/tick and252.8–253.4MiB/s allocation, while stock/fallback did equivalent complete work around0.2–0.27ms/tick. A4-furnace regression control recorded5catalog reads (one per initial invocation plus one independent fresh pass). JFR shows resource table/planning and catalog work on the server while actual worker CPU is about4% of a core. The fix shares only one `FurnaceWorkPreparation` and whole-phase alias observation within a still-unexecuted canonical prefix. It discards both before every execute and serial fence. Original held-region/mailbox fresh preparation, whole-phase alias recapture, Claims identity checks, logical binding budgets, all-or-none reservations, Kernel permits and ordered notifications are untouched. The new control requires2audits and still4real Worker completions; another test mutates a recipe result at a serial fence and proves suffix fallback against the serial oracle. Allocation falls to18.7MiB/s and unsampled means2.34–3.09ms. No catalog cache survives a fence or tick. This corrects a substantial existing regression without weakening C6.

3. **Fixed executor termination precedes physical Thread return.** An actual worker-failure/join control observed `close()` return before the last fixed-worker Thread's `isAlive` cleared. This is not a fake timing assertion: the lifecycle requires physical join. After ordinary executor shutdown/termination, the existing original threads are now explicitly joined with interruption restored after completion, matching the persistent close path. The exact failing assertion remains unchanged and passes in both pool controls. Accepted tasks still run; shutdown does not discard queues or replay started work. Original failing XML remains retained.

4. **Monitoring state shared across server threads.** Full-suite execution reproduced native-ring samples0/2where the controlled server had recorded exactly1; a later diagnostic read saw an empty history while collection was enabled. The process-wide current-server slot could be replaced by another server thread between its identity check and history read. Collection is now confined to the owning server thread through a ThreadLocal with a weak server reference. Tick events and commands already execute there. A deterministic two-server-thread test requires independent samples and refuses cross-server clearing; it uses no global metrics lock. The original ring-slot/quantile assertions remain unchanged. A final review also keeps alias scanning behind the original successful-candidate check; an ineligible furnace must enter its complete serial body before inventory probing.

Final `.100` actual stopped-world GC controls independently certify Fixed and Persistent after the monitoring changes:4observed collections,28cleared/enqueued references, engine+6real callbacks retained,12post-retirement foreign refusals and zero original/observer/Gradle exits per profile.
